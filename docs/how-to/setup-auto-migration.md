# How to set up auto-migration

## Goal

Set up auto-migration in your backend and client code to be ready for syncing.

Your backend app stores data in PostgreSQL and your client app in a local SQLite
database. When you ship a new version of your app with schema changes, the
production database and existing client installs still have the old schema.
Auto-migration reconciles each database with your declared schema at startup,
creating missing tables and columns as needed, without shipping hand-written
migration scripts.

## Prerequisites

- Experience setting up carburetor sync.

## Steps

### 1. Enable the migration feature

Both the backend and client builds of `carburetor` need the `migration`
feature:

```toml
carburetor = { version = "0.2.0", features = ["migration"] }
```

### 2. Run migrations at startup

On top of your existing backend setup, add the following:

```rust
use diesel::prelude::*;
use carburetor::config::{initialize_carburetor_global_config, CarburetorGlobalConfig};

initialize_carburetor_global_config(CarburetorGlobalConfig {
    database_url,
});

let mut connection =
    PgConnection::establish(&database_url).expect("Error connecting to database");

// Run migrations before any other database or sync operation, so sync code
// never touches a table or column that does not exist yet.
run_migrations(&mut connection)?;
```

`run_migrations` is generated by the `carburetor_sync_config!` macro and is in
scope where the macro is declared; adjust the call path to match your module
layout.

The generated signature is:

```rust
pub fn run_migrations(conn: &mut diesel::PgConnection)
    -> Result<(), carburetor::error::Error>
```

### 3. Make the migration feature work for the client

On the client, `run_migrations` is generated inside the sync group's module and
covers only that group's tables (plus `carburetor_offsets`). This guide uses a
single sync group, `user`.

On top of your existing client setup, add the following (adjust the call path to
match your module layout):

```rust
use carburetor::error::Error;
use diesel::prelude::*;

let mut connection =
    SqliteConnection::establish(&database_path).expect("Error connecting to database");

// `user` is a sync group; its `run_migrations` lives in its module.
match user::run_migrations(&mut connection) {
    Ok(()) => {}
    Err(Error::DatabaseWiped { source }) => {
        // The local database was unrecoverably out of sync with the declared
        // schema, so it was wiped and recreated. Inform the user that local
        // data was reset; the next download re-syncs everything from the
        // backend automatically.
        eprintln!("Local database was reset: {source}");
    }
    Err(err) => return Err(err),
}
```

See [reset to a clean state](../explanation/client-migration-reset-to-clean-state.md)
for why the reset happens and how the client recovers its data.

The generated signature is scoped to the group's module:

```rust
pub fn run_migrations(conn: &mut diesel::SqliteConnection)
    -> Result<(), carburetor::error::Error>
```

Auto-migration only applies to a subset of operation patterns. See the
[migration guide](../reference/migration-patterns.md) (TODO) for which patterns
